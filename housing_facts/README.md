# База знаний об аренде в Батуми (по методу Карпати / LLM Wiki)

Этот справочник устроен по принципу **LLM Wiki**: разделение на «сырые» исходники и «компилируемую» базу знаний, которую обновляет и поддерживает ИИ-ассистент на основе присылаемых материалов.

## Структура директории

- housing_facts/
  - README.md: описание базы знаний и правила её ведения.
  - raw/: "входящие" сырые материалы (транскрипты, суммаризации, ссылки, личный опыт).
  - wiki/: структурированная, постоянно обновляемая ИИ база знаний.
    - general.md: общие правила аренды (отопление, плесень, сезонность, коммуналка).
    - buildings/: заметки о конкретных жилых комплексах (ЖК) и адресах.

## Инструкция для ИИ-агентов по наполнению базы знаний

Когда пользователь присылает выжимки, статьи или отзывы, агент обязан выполнить следующие шаги:

1. **Сохранить источник в `raw/`**: Создать файл в формате `housing_facts/raw/<slug_источника>.md` и сохранить туда исходный текст или суммаризацию, добавив дату и ссылку (если есть).
2. **Обновить или создать документы в `wiki/`**:
   - Выделить из источника общую информацию (цены, законы, общие советы) и обновить `housing_facts/wiki/general.md`.
   - Выделить информацию по конкретным домам, комплексам или улицам. Создать для них отдельные файлы в `housing_facts/wiki/buildings/<name>.md` (или обновить существующие) по шаблону `template.md`.
3. **Оформить ссылки (Backlinks)**:
   - Любое утверждение в файлах `wiki/` должно сопровождаться кликабельной ссылкой на строку/раздел в сыром источнике `raw/`.
   - Формат ссылки: `[[Источник](file:///Users/dmemruk/development/services/apartment-hunter/housing_facts/raw/<file>.md#L<line>)]`.
4. **Не использовать лишние символы**: Избегать схем с псевдографикой (вертикальные и горизонтальные линии, стрелочки), расходующие контекстные токены. Использовать только простой компактный markdown-список.
